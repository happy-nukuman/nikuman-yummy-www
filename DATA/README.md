# Open data workspace

`DATA` は、公開データをアプリの Contract に合わせて取り込み、正規化し、検証するための作業領域です。

## Directory roles

- `raw/`: ダウンロードした原本。再配布可能性を確認するまで Git に追加しません。
- `normalized/`: `@nikuman-yummy/shared` の `Shelter` などに変換した成果物。
- `scripts/`: 変換、検証、メタデータ付与を行うスクリプト。`scripts/lib/` は ZIP / XLSX / DBF / SHP / 測地系変換の最小実装（Node 標準ライブラリのみ、npm 依存を追加しないため）。

各データソースについて、データ名、提供元、ライセンス、原始 URL、取得日、更新頻度、変換方法を同じ Pull Request で記録してください。個人情報、Token、Secret、または再配布が許可されていないデータは保存しません。

小さく再配布可能なデータのみ、レビュー後に明示的に Git 管理へ追加します。大きなデータや高頻度更新データは将来 R2 などへの移行を検討しますが、本タスクでは Cloudflare リソースを作成しません。

### seed SQL の分割規則（D1 の制約）

**Cloudflare D1 は 1 文が約 100KB を超えると `SQLITE_TOOBIG` で拒否します。** `sqlite3` CLI の既定上限は 1MB なので、ローカルの `sqlite3` で通っても D1 で失敗します（実際に `stay-put-zones.seed.sql` で発生）。

そのため両パイプラインは共通ヘルパー `buildInsertStatements`（`DATA/scripts/lib/tokyo.ts`）で INSERT を分割し、**行数（50 行）とバイト数（90,000 バイト）の両方**を上限にしています。ポリゴンを含む行のように 1 行が大きい場合はバイト数が先に効き、1 文あたりの行数が減ります。1 行だけで上限を超える行があればビルドを停止して報告します（黙って捨てたり、勝手に簡略化を強めたりしません）。

検証は必ず `sqlite3` ではなく wrangler で行ってください。

```bash
cd BACKEND/japan-disaster-relief-api
npx wrangler d1 execute japan-disaster-relief-db --local --file ../../DATA/normalized/facilities.seed.sql
npx wrangler d1 execute japan-disaster-relief-db --local --file ../../DATA/normalized/stay-put-zones.seed.sql
```

現状: `facilities.seed.sql` は 95 文（最大 16,985 バイト / 50 行、行数が先に効く）、`stay-put-zones.seed.sql` は 5 文（最大 89,369 バイト / 13 行、最大の 1 行は 19,459 バイト）。

- `DATA/normalized/facilities.seed.sql`（`facilities` / `dataset_meta` 用の seed）

### 変換内容（共通）

- **文字コード**: 避難所 CSV は Shift_JIS、避難場所 CSV は UTF-8 BOM 付き。内容から判定して復号します。
- **ヘッダー行**: 先頭に空行が入るため、ヘッダー行を探索し列名で列位置を解決します（列順の変更に耐えるため）。
- **施設種別**: 避難所 CSV → `evacuation_shelter`（指定避難所）、避難場所 CSV および都市整備局データ → `evacuation_area`（避難場所／指定緊急避難場所）。
- **市区町村コード**: 出典の 6 桁コード（検査数字付き）は 5 桁の総務省コードに対応しますが、コード列より **市区町村名列と住所を優先** します（出典側の誤りがあるため、下記「既知の制約」参照）。
- **都指定の避難場所**: 避難場所 CSV の 235 行はコード列が `130001`（都）で市区町村名が「東京都」です。住所の先頭市区町村名から解決し、住所に市区町村名が無い 28 行は、**同じデータセット内で市区町村が確定した行から作った町名インデックス**で一意に解決しました（外部知識ではなくデータ由来）。解決できない行はスキップします。
- **座標検証**: 緯度 35.4〜36.0、経度 138.7〜140.1（東京都本土域）の範囲外はスキップし、理由別に計数します。
- **重複排除**: 施設種別・市区町村・**施設名（原文そのまま）** が同一で 200m 以内の組は同一施設とみなし、住所がより詳細な 1 件を残します。括弧内は識別情報なので原文で比較します（例: 三鷹市「第一小学校（体育館・校舎）」と「（校庭）」、町田市「ゆくのき学園（武蔵岡中学校）」と「（大戸小学校）」は別施設として保持）。
- **`name`**: 出典に日本語名のみのため `ja` のみ。**機械翻訳は行いません**（`en` / `zhHans` は出力しません）。
- **`accessibility`**: 出典の 4 つの「○」列を安定した slug に対応させ、自由記述列は `other:<原文>` として保持します。情報が無い場合は `[]`。
  - `エレベーター有/避難スペースが１階` → `elevator_or_ground_floor_space`
  - `スロープ等` → `slope`
  - `点字ブロック` → `braille_blocks`
  - `車椅子使用者対応トイレ` → `wheelchair_accessible_toilet`
  - `その他` / `その他（具体的に）` → `other:自動ドア` のように原文を保持
- **`sourceUrl` / `sourceUpdatedAt`**: ソース 1 のレコードは取得元 CSV の直接 URL とその公開日。ソース 2 のレコードは**データセットページの URL**（1 レコードが xlsx の属性と SHP の座標を組み合わせるため、単一ファイルを指せない）と `2022-09-01`。
- **文字列整形**: 前後の空白除去と連続空白の 1 個への圧縮のみ。名称・住所の中身は書き換えません。

### `facilityId`（**旧 seed と非互換 — 全件再投入が必要**）

```text
facilityId = <5桁市区町村コード>-<hash8>
hash8      = SHA-256( "<municipalityId>|<facilityType>|<NFKC正規化 name.ja>|<NFKC正規化 address>" )
             の先頭 8 桁（小文字16進）
```

内容から決まる ID なので、データ更新や並び順の変更でも既存 ID が変わりません（旧方式は市区町村内の連番だったため、1 件追加すると同一市区町村の ID が全てずれました）。ビルド時に全体の一意性を検証し、衝突したらエラーで停止します。

**旧 seed の `13101-0001` 形式の ID とは互換性がありません。** ブックマーク・キャッシュ・保存済み ID は無効になります。D1 は `DELETE` を含む seed で全件置き換えてください。

### Stage A: 複数区にまたがる避難場所

広域避難場所の `所在地` は複数の市区町村を列挙します（CSV は `、` 区切り、xlsx は改行区切り、1 件のみ `及び`）。従来は**先頭の 1 市区町村だけ**を採用していたため、隣接区の広域避難場所が当該区のデータから落ちていました。現在は列挙された市区町村ごとに 1 レコードを出力します（同一施設が複数市区町村に現れるのは意図した動作です）。

```text
"港区北青山、新宿区霞ヶ丘町、渋谷区神宮前、千駄ケ谷" → 港区 / 新宿区 / 渋谷区 の 3 レコード
```

市区町村名は**各セグメントの先頭でのみ**照合します。`岩淵町` や `代々木神園町` のような「町」で終わる町名を市区町村と誤認しないためです。セグメントが 1 件しか市区町村を含まない場合は、（正確な）市区町村名列の解決結果を優先します。

### Stage B: 都市整備局 第9回指定の統合

- **座標**: xlsx に緯度経度は無いため、SHP のポリゴン重心を使用します。SHP は `JGD2000 / 平面直角座標系第9系`（EPSG:2451）なので、逆変換（Transverse Mercator の逆解）で WGS84 に変換します。実装は `DATA/scripts/lib/binary-formats.ts`（ZIP / XLSX / DBF / SHP / 投影変換をすべて Node 標準ライブラリのみで実装、npm 依存なし）。
  - 検証: 名称一致した 194 件でソース 1 の代表点と比較し、**中央値 94m / p90 412m / 最大 3.3km**（最大値は河川敷など細長いポリゴンで、重心が代表点として粗くなるケース）。
- **市区町村の割り当て**: `所在地`（**物理的な所在地**）で判定します。データセットには「地区割当」（どの区の町丁がその避難場所に割り当てられているか）もありますが、Stage C 扱いで未使用です。この判断により、渋谷区恵比寿南に一部かかる `中目黒公園一帯` は渋谷区に**含まれ**、渋谷区本町三丁目が割り当てられているが物理的に新宿区内の `新宿中央公園・高層ビル群一帯` は渋谷区に**含まれません**。
- **重複判定**: 同一市区町村・同一施設種別の既存レコードと、**正規化名**（NFKC、`ヶ`→`ケ`、`・`・空白・括弧内を除去）で照合します。完全一致・包含・部分列（長い方の 60% 以上）のいずれかで一致し、かつ 5km 以内なら同一施設とみなし、**ソース 1 のレコードを残します**（住所がより詳細で、バリアフリー情報を持つため）。距離は名称の偶然一致を棄却するためだけに使い、一致の根拠にはしません。
  - 出版元間の表記揺れを吸収した例: `水元公園` / `水元公園・江戸川緑地一帯`（包含）、`篠崎公園` / `篠崎公園・江戸川緑地一帯`（包含）、`練馬総合運動場一帯` / `練馬総合運動場公園一帯`（部分列）、`墨田区役所・隅田公園広場一帯` / `墨田区役所・隅田公園自由広場一帯`（部分列）。
- **追加レコード**: `accessibility` は `[]`（出典に情報なし）。`address` は原文のまま採用しますが、**町名レベルまでで丁目・番地がありません**（例: `渋谷区神南、代々木神園町`）。ソース 1 由来のレコードより粗い住所です。

## データ台帳: 地区内残留地区（Stage C）

### なぜ必要か（安全上の根拠）

東京都は震災対策条例に基づき、**不燃領域率が十分に高い市街地を「地区内残留地区」に指定**しています。この地区の住民は**広域避難場所に割り当てられておらず、その場に留まることが公式の指示**です。

この層が無いと、アプリは渋谷・道玄坂のような残留地区の利用者に対して、数 km 離れた避難場所を「最も近い避難場所」として提示し、あたかもそこへ向かうべきかのように読ませてしまいます。これは公式指定と矛盾します。**残留地区では「近くに避難場所が無い」ことが正しい情報であり、その理由を説明する必要があります。**

内部の整合性も確認できます: `中目黒公園一帯`（避難場所）の所在地には渋谷区恵比寿南が含まれますが、渋谷区の町丁は 1 つも割り当てられていません。恵比寿南が残留地区に含まれているためです。

### ソース

Stage B と**同一のデータセット**（東京都都市整備局「震災時火災における避難場所等の指定（第9回）」、CC BY 4.0、`sourceUpdatedAt` = 2022-09-01、更新頻度 概ね5年ごと）の別リソースです。帰属表示も Stage B と同じ文言を使用します。

| 入力 | 内容 |

| `DATA/raw/hinan02_02_stay_put_zones_shp.zip` | 地区境界のポリゴン（レイヤ `第９回地区内残留地区`、EPSG:2451） |

### 実行

```bash
npx tsx DATA/scripts/normalize-stay-put-zones.ts
```

出力（Git 管理外）: `DATA/normalized/stay-put-zones.json` / `DATA/normalized/stay-put-zones.seed.sql`（BACKEND のマイグレーション `0004` が作る `stay_put_zones` テーブル用）。**facilities 側の出力は変更しません。**

### 抽出方法

- **行のグルーピング**: 番号のある行が地区の開始、以降の行が同一地区の別市区町村です。市区町村ごとに 1 レコードを出力し、町丁リストはその市区町村の分だけに絞ります。
- **`zoneId`**: `zone-<5桁市区町村コード>-<hash8>`。`hash8` = SHA-256(`"<municipalityId>|<NFKC正規化 name.ja>"`) の先頭 8 桁（小文字16進）。facilities と同じ方式で、ビルド時に一意性を検証します。
- **町丁の展開規則**: 出典は `、` 区切りで、最後の 1 件のみ `及び` で連結します（例: `勝どき五丁目、勝どき六丁目及び豊海町` → 3 件）。`、`／`及び`／`並びに` で分割し、各要素は**原文のまま**保持します（`…の一部` = その丁目の一部のみが地区に含まれる、という情報を残すため）。本データセットに `一・二丁目` のような圧縮表記は**存在しない**（該当 0 行）ため、この分割は可逆であり、未展開の生文字列を別途保持する必要はありません。
- **面積・人口**: 出典は**地区全体の値のみ**を公開しています。複数市区町村にまたがる地区では、按分を発明せず**すべてのレコードで `null`** にします（下記の失われる値の一覧を参照）。単一市区町村の地区はそのまま採用し、Excel の浮動小数ノイズを除くため小数 4 桁に丸めます（出典の記載精度が 4 桁）。
- **`polygon`**: **公開されています。** 逆変換（EPSG:2451 → WGS84）してリングの配列で出力します。各リングは `[緯度, 経度]` の配列で、面積の大きい順（外周が先頭）です。
  - このデータセットのリングは**すべて外周**（穴なし）で、複数リングは飛び地を表します（例: 青海・東八潮・台場地区は 5 リング）。
  - 面積 1 m² 未満の退化リングは除外します（1 件）。
  - 1 リングが 500 点を超える場合のみ Ramer-Douglas-Peucker（許容誤差 **10m**、投影座標＝メートル上で実施）で簡略化します。該当 3 リング: 591→110 / 513→73 / 565→80 点。**面積の変化は -0.075%〜+0.226%** です。
  - 分割された地区でも**全レコードに地区全体の境界**を入れます（市区町村で切り抜いていません）。「利用者は残留地区の中にいるか」という判定に必要なのは地区全体の形状だからです。

### 既知の制約（避難施設データ）

- **島しょ部が含まれません**: 大島町・利島村・新島村・神津島村・三宅村・御蔵島村・八丈町・青ヶ島村・小笠原村の 208 件は、Contract が定める本土域の座標範囲外のためスキップしています。島しょ部に対応する場合は範囲の見直しが必要です。
- **渋谷都心部は「地区内残留地区」**: 渋谷区の 26 町丁（374.95ha、退避人口 191,122 人）は広域避難場所に割り当てられていません。詳細は上記「データ台帳: 地区内残留地区（Stage C）」を参照。Stage C として実装済みですが、UI での提示方法は A 組の判断待ちです。
- **ソース 2 は区部のみ**: 多摩地域・島しょ部の避難場所はソース 1 のみに依存します。
- **ソース 2 の住所は町名レベル**: 丁目・番地がありません。距離表示や地図表示ではポリゴン重心を指すため、実際の出入口とは数百 m ずれることがあります（避難場所は「建物」ではなく「区域」なので、ある程度は仕様です）。
- **出典のコード誤り**: 避難所 CSV の中野区 38 行が中央区のコード `131024` を持っています。市区町村名列・住所（いずれも中野区）を優先して `13114` に割り当て、スクリプトの実行サマリに件数を出力します。区ごとの件数は中央区 23 件 / 中野区 45 件です。
- **同一施設名の並存**: 出典が意図的に分けて掲載している 29 組（三鷹市の「体育館・校舎」と「校庭」22 組、江戸川区の「（夜間）」2 組、町田市「ゆくのき学園」2 組、武蔵村山市「総合運動公園運動場（第一〜第三）」など）は、正規化名では同名になりますが別レコードとして保持しています。Stage B の統合により生じた重複は 0 件です。
- **開設状況は不明**: 実際に開設しているか、混雑しているか、通行可能かは本データに含まれません。UI では `not_realtime` として扱い、「データに存在する」を「現在開設中」と表示してはいけません。
- **基準日が古い**: ソース 1 は 2021-04-01 基準、ソース 2 は 2022-09-01 適用です。統廃合・新設の反映が遅れている可能性があります。表示時は必ず出典と基準日を併記してください。
- **多言語名なし**: 施設名は日本語のみです。英語・中国語名はどちらの出典にも存在しないため、翻訳が必要な場合は別途検証済みデータの用意が必要です。
- **未使用の出典項目**: 避難場所 CSV には対応災害種別（洪水・崖崩れ・高潮・地震・津波・大規模な火事・内水氾濫・火山現象・その他）の列、都市整備局データには避難有効面積・避難計画人口・地区割当・避難道路があります。現在の Contract に対応項目が無いため取り込んでいません。

## Validation

正規化した shelter JSON 配列は、リポジトリルートから次のように検証できます。

```bash
npm run data:validate -- DATA/normalized/shelters.json
```

このコマンドは Shared Contract の runtime guard を使用します。

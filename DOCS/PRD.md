## 0. 阅读说明

本文将内容分为三种状态：

- **确定**：开发组可以据此设计和实现；
- **建议**：A组当前推荐方案，可用于技术评估；
- **待确认**：未确认前不得写死为正式业务规则。

优先级定义：

- **P0**：比赛版本必须完成，缺少后主流程或安全边界无法成立；
- **P1**：P0稳定后再做，可明显增强体验或评分；
- **P2**：比赛后扩展；
- **暂缓**：缺少数据、官方依据或可靠实现方式；
- **不做**：超出本产品阶段或存在较高误导风险。

## 1. 产品定义

### 1.1 一句话定义

Tokyo Safe First是一款为在东京生活或短期停留的外国人优先设计、任何人都能使用的PWA应急行动引导工具。

当用户已经暂时脱离眼前直接危险，却不知道下一步去哪里、做什么或如何求助时，系统结合用户当前状态、临时位置、东京都行政开放数据和经过核验的固定规则，以多语言行动卡逐步给出下一步指引。

### 1.2 核心价值

```text
用户当前情况
＋ 临时地理位置
＋ 官方行政数据
＋ 经核验的固定规则
→ 当前应该完成的一步行动
```

本产品不是：

- 普通地图或设施搜索服务；
- 自由问答AI；
- 建筑安全鉴定工具；
- 实时灾害指挥系统；
- 警察、消防、医疗机构或现场工作人员的替代品。

### 1.3 服务起点

**确定：**

- 产品不处理强烈摇晃仍在持续、建筑正在倒塌或用户必须立即逃生的复杂操作阶段；
- 产品从用户已经完成第一时间避险或撤离、暂时离开眼前直接危险后开始；
- “灾后30分钟”指用户脱离第一时间危险后，建立下一步行动方向的关键阶段，不承诺解决完整避难过程。

若用户表示仍处于直接危险，系统不进入完整问答，只显示经过核验的简短提示和求助入口。

## 2. 用户范围

### 2.1 核心用户

**第一核心用户：**

- 在东京生活、留学或工作的外国人；
- 日语能力有限；
- 不熟悉日本防灾制度、设施类型和现场指示。

**第二核心用户：**

- 短期外国游客；
- 儿童；
- 行动不便者；
- 老年人；
- 灾后因惊慌暂时无法判断的人。

### 2.2 对外表达

统一表述：

> 为外国人优先设计，任何人都能使用。

不得表述为“仅限外国人”。

## 3. MVP范围

### 3.1 P0主Demo

**确定：**

> 一名只会中文的外国人在东京经历大规模地震，已经从建筑物撤离到室外，但不知道下一步怎么办。用户打开PWA，系统推荐中文；用户确认语言并授权本次位置；系统询问当前环境和三个风险问题；固定规则生成行动卡；开放数据改变设施候选结果；最后展示日语沟通卡。

主Demo环境固定为“室外”。

### 3.2 P0端到端流程

```text
打开PWA
→ 推荐界面语言
→ 用户确认或手动切换
→ 选择灾害模式
→ 确认是否已经脱离直接危险
→ 获取本次位置或手动选择行政区域
→ 选择当前环境
→ 回答三个风险问题
→ 固定规则计算用户状态
→ 显示当前行动卡
→ 用户选择已完成/做不到/不确定/需要帮助
→ 显示下一张行动卡
→ 必要时显示设施候选
→ 展示多语言沟通卡
→ 展示数据来源、更新时间和限制
```

### 3.3 本版范围取舍

| 项目 | 版本范围 |
|---|---|
| 灾害模式 | P0完整实现主流程 |
| 日常应急入口 | P0展示入口和说明 |
| 完整日常应急场景 | P1，建议先做一个场景 |
| 首发语言 | P0：中文、英文、日语 |
| 环境入口 | P0：建筑物内、室外、交通设施 |
| 完整离线流程 | 本版不做 |
| 极简网络异常页 | P0 |
| 自动识别灾害并强制切换 | 不做 |
| AI自由决定行动 | 不做 |

| ID | 页面/组件 | 优先级 | 主要内容 |
|---|---|---:|---|
| UI-01 | 启动页 | P0 | 产品名称、语言推荐、手动切换 |
| UI-02 | 模式选择页 | P0 | 灾害模式、日常应急入口 |
| UI-03 | 服务边界确认页 | P0 | 是否已脱离直接危险 |
| UI-04 | 定位授权页 | P0 | 获取本次位置、拒绝说明、手动选区 |
| UI-05 | 环境选择页 | P0 | 建筑物内、室外、交通设施 |
| UI-06 | 风险问题页 | P0 | 每页一个问题；是/否/不确定 |
| UI-07 | 行动卡页 | P0 | 当前行动、原因、下一步、替代路径 |
| UI-08 | 设施候选页 | P0 | 名称、类型、地址、距离、来源、状态 |

### 4.1 通用导航要求

- 用户可随时切换语言；
- 用户可返回上一步，但返回后必须重新计算后续结果；
- 用户可随时打开“我需要帮助”和沟通卡；
- 高风险页面不得只有颜色差异，必须同时使用文字或图标；
- 不要求注册或登录；
- 不收集姓名、在留资格和具体住址。

## 5. 功能要件

### FR-01 PWA入口

**优先级：P0**

- 手机浏览器可打开并完成主流程；
- 支持添加到主屏幕；
- 不需要注册；
- 比赛演示环境下流程稳定；
- 优先保证加载速度和操作稳定，不以复杂动画为目标。

**验收：**

1. 支持团队确定的主流手机浏览器；
2. 首次访问可进入语言页；
3. 不中断地完成主Demo；
4. 连续演示三次无阻断性错误。

### FR-02 语言推荐与切换

**优先级：P0**

- 读取浏览器语言偏好并推荐中文、英文或日语；
- 无匹配语言时使用默认语言；
- 用户必须可以手动切换；
- 切换语言后保留当前流程状态；
- 安全关键按钮、行动规则和沟通卡使用审核过的固定语言包；
- 浏览器语言识别不调用AI。

**待确认：**默认回退语言是英文还是日语。

### FR-03 使用模式

**优先级：P0**

- 首页提供“灾害模式”和“日常应急”两个入口；
- P0完整实现灾害模式；
- 日常应急入口可以先展示功能说明；
- 有可靠官方灾害信息时可突出推荐灾害模式；
- 不得在缺少可靠信息时自动强制进入灾害模式；
- 用户始终可以手动选择或切换。

### FR-04 直接危险确认

**优先级：P0**

进入完整流程前询问用户是否已经暂时脱离眼前直接危险。

| 用户回答 | 系统行为 |
|---|---|
| 是 | 进入位置和环境选择 |
| 否 | 显示简短固定提示与求助入口，不进入复杂问答 |
| 不确定 | 按高风险分支显示固定提示与求助入口 |

具体提示文案和官方依据必须由A组确认后进入正式语言包。

### FR-05 临时位置

**优先级：P0**

- 仅在用户主动授权后获取位置；
- 位置只用于本次行政区域和设施候选匹配；
- 默认不保存位置历史；
- 用户拒绝或定位失败时，可手动选择区市町村；
- 定位中必须显示状态；
- 超时后不得让用户无限等待。

**P1：**选择车站或输入地标。

**建议默认超时：**8秒，由开发组按浏览器实际表现评估。

### FR-06 当前环境

**优先级：P0**

提供三个选项：

1. 建筑物内；
2. 室外；
3. 交通工具或车站内。

交通设施第一版只提供基础引导，提醒遵循工作人员和运营方指示，不进行复杂路线判断。

### FR-07 三个风险问题

**优先级：P0**

当前候选问题：

1. 附近是否仍有火焰、烟雾或其他明显危险？
2. 自己或身边的人是否严重受伤、无法移动或失去意识？
3. 是否因语言、年龄、行动不便等原因需要帮助？

每题必须：

- 单页显示；
- 提供“是/否/不确定”；
- 用户凭观察即可回答；
- 每个答案改变用户状态或下一张行动卡；
- 文案及分支有官方依据；
- 不由AI生成问题或结论。

**待确认：**以上三个问题的最终文案、顺序和官方依据。饼叔牵头，A组三人共同确认。

### FR-08 用户状态

**优先级：P0**

系统至少支持以下内部状态：

- `safe`：未识别到当前高风险；
- `uncertain`：用户选择不确定或关键数据缺失；
- `danger`：存在明显危险或严重受伤；
- `need_help`：用户明确需要协助或无法完成行动。

状态由固定规则计算，同一输入必须得到同一结果。

**注意：**这些是系统流程状态，不是对建筑、路线或用户医学情况的专业判断。

### FR-09 行动卡

**优先级：P0**

行动卡类型：

- 事件/边界确认卡；
- 状态确认卡；
- 动作卡；
- 避难确认卡；
- 设施候选卡；
- 沟通卡。

每张行动卡最多突出一项主行动，并包含：

1. 现在最重要的一件事；
2. 为什么要做；
3. 接下来可以做什么；
4. 暂时不要做什么；
5. 无法完成时如何求助；
6. 必要时的设施候选或官方入口；
7. 数据最后更新时间；
8. 官方依据或来源。

固定操作：

- 我已完成；
- 我做不到；
- 我不确定；
- 我需要帮助；
- 显示给身边的人。

### FR-10 固定行动规则

**优先级：P0**

- 规则以可检查的配置或程序逻辑保存；
- 相同输入产生相同状态和行动卡；
- 每个高风险动作必须关联官方依据；
- 没有官方依据的分支不得进入正式比赛版本；
- AI接口失败不得改变固定规则结果；
- 修改规则时需要记录规则版本。

**建议规则记录字段：**

```text
rule_id
rule_version
mode
environment
question_answers
result_state
card_id
source_id
effective_date
review_status
```

### FR-11 开放数据匹配

**优先级：P0**

至少有一项东京都或区市町村开放数据真实改变页面结果。

处理流程：

```text
本次位置或手选区域
→ 判定行政区域
→ 读取设施数据
→ 按设施类型和距离筛选
→ 输出设施候选
```

必须展示：

- 数据来源；
- 数据最后更新时间；
- 数据是否实时；
- 当前无法确认的事项。

仅展示数据链接不视为完成开放数据活用。

### FR-12 设施候选

**优先级：P0**

每条设施候选至少包含：

- 名称；
- 设施类型；
- 地址；
- 大致距离；
- 数据来源；
- 最后更新时间；
- 当前开放状态是否可以确认。

输出用语必须遵守：

- “附近”不等于“安全”；
- “数据中存在”不等于“当前开放”；
- “距离最短”不等于“路线可通行”；
- 不使用“最安全路线”“一定开放”等无法验证的表达。

### FR-13 沟通卡

**优先级：P0**

建议首批固定沟通卡：

- 请帮帮我；
- 请帮我叫救护车；
- 请告诉我避难地点；
- 我不会说日语；
- 我需要特殊帮助；
- 我需要药物或有过敏；
- 我是独自行动的儿童。

最低功能：

- 同时显示当前界面语言和日语；
- 日语大字号；
- 可全屏展示；
- 用户可从主要页面快速打开；
- 文案使用审核过的固定翻译。

### FR-14 官方来源与限制

**优先级：P0**

所有安全相关结果页必须说明：

- 行动规则或信息来源；
- 数据最后更新时间；
- 是否为实时信息；
- 无法确认的事项；
- 产品不能替代警察、消防、医疗机构和现场工作人员判断。

### FR-15 网络异常与降级

**优先级：P0**

第一版不实现完整离线流程，也不宣传“断网可完整使用”。

网络请求失败时：

- 不显示空白页；
- 不继续展示可能过期的实时结论；
- 显示“当前服务受限”；
- 保留语言切换；
- 显示经过核验的基础求助信息；
- 提醒用户确认现场广播、工作人员和官方信息；
- 提供重试入口。

**建议：**缓存极简网络异常页。是否采用Service Worker实现，由开发组评估。

## 6. 数据要件

### 6.1 设施数据最小字段

| 字段 | 必填 | 说明 |
|---|---:|---|
| facility_id | 是 | 内部唯一标识 |
| name_ja | 是 | 日文设施名称 |
| name_localized | 否 | 已核验的多语言名称 |
| facility_type | 是 | 避难场所、避难所等类型 |
| municipality | 是 | 区市町村 |
| address | 是 | 地址 |
| latitude | 是 | 纬度 |
| longitude | 是 | 经度 |
| accessibility | 否 | 无障碍属性 |
| source_url | 是 | 官方来源 |
| source_updated_at | 是 | 来源更新时间 |
| open_status | 否 | 仅在有可靠数据时使用 |
| status_updated_at | 否 | 状态更新时间 |

### 6.2 数据状态

界面统一使用以下状态：

- `confirmed`：存在可靠且有效期明确的数据；
- `not_realtime`：数据存在，但不是实时开放状态；
- `unknown`：无法确认；
- `unavailable`：数据请求失败。

禁止把`not_realtime`或`unknown`显示为“已开放”。

### 6.3 位置数据

- 浏览器位置坐标只在本次会话内使用；
- 默认不写入长期存储、分析平台或日志；
- 前后端日志不得记录精确坐标；
- 若技术上必须短期缓存，开发前需提交保存目的、有效期和删除机制供A组确认。

## 7. AI要件与安全边界

### 7.1 AI允许负责

- 简化非关键官方说明；
- 辅助翻译非安全关键内容；
- 解释行政或防灾术语；
- 对确定性程序已经生成的候选结果进行易懂说明。

### 7.2 AI不得负责

- 判断建筑是否安全；
- 决定用户是否必须避难；
- 判断设施是否已经开放；
- 声称路线安全；
- 自由生成医疗、消防或救援建议；
- 修改固定规则产生的状态和行动结论。

### 7.3 AI失败时

- 固定规则和核心卡片仍可工作；
- 页面不得卡死；
- 不把模型错误信息直接展示给用户；
- 回退到固定语言包；
- 记录不含个人位置的技术错误。

P0只建议展示一个低风险AI能力；没有稳定实现和回退方案时，可不在主Demo中启用AI。

## 8. 非功能要件

### NFR-01 易用性

- 主要任务按钮适合单手触控；
- 每页只要求用户完成一个主要动作；
- 关键操作不依赖长文本阅读；
- 返回后不产生相互矛盾的结果；
- 两分钟内可完成主Demo。

### NFR-02 无障碍

**P0：**

- 大字号；
- 高对比度；
- 图标和短文字并用；
- 不只用颜色表达状态；
- 全屏沟通卡；
- 操作元素具备可识别标签。

**P1：**

- 文字朗读；
- 更完整的视力、听力和药物需求入口；
- 设施无障碍条件筛选。

语音不得作为听力障碍用户的唯一信息方式。

### NFR-03 性能与稳定性

- 首屏和核心页面应优先加载；
- 数据请求显示加载、成功、空结果和失败状态；
- 定位与接口请求必须有超时和重试；
- 快速重复点击不得产生重复页面或错误状态；
- 比赛演示前在目标手机和网络环境完成压力较低但完整的重复测试。

具体性能秒数由C组根据部署环境提出并记录。

### NFR-04 隐私

- 不要求账户；
- 不收集姓名、住址或在留资格；
- 默认不保存精确位置历史；
- 获取位置前说明用途；
- 用户拒绝定位后仍可继续使用。

### NFR-05 可维护性

- 语言文案、规则、设施类型和来源信息应与页面代码分离；
- 规则和语言包需要版本号；
- 数据源变化不应要求重写核心页面；
- 测试环境和比赛演示环境使用相同的规则版本。

## 9. 异常处理矩阵

| 异常 | 系统行为 | 是否阻断 |
|---|---|---:|
| 用户拒绝定位 | 转为手动选择区市町村 | 否 |
| 定位超时/失败 | 显示原因和重试，提供手动选区 | 否 |
| 行政区域无法匹配 | 要求用户手动选择区域 | 否 |
| 设施数据为空 | 不推荐设施，显示官方入口和限制 | 否 |
| 设施接口失败 | 显示服务受限，不声称设施开放 | 否 |
| AI接口失败 | 使用固定规则和固定语言包 | 否 |
| 浏览器语言不支持 | 使用默认语言并允许手动切换 | 否 |
| 网络中断 | 进入极简异常页 | 部分阻断 |
| 用户选择“不确定” | 进入保守的固定规则分支 | 否 |
| 用户选择“我做不到” | 显示替代动作或沟通卡 | 否 |
| 用户仍处于直接危险 | 停止复杂问答，显示固定求助提示 | 是 |

## 10. 最小接口约定

以下为前后端联调所需的逻辑接口，不限制具体URL命名。

### 10.1 行政区域匹配

**输入：**

```json
{
  "latitude": 35.0,
  "longitude": 139.0
}
```

**输出：**

```json
{
  "municipalityId": "string",
  "municipalityName": "string",
  "matched": true
}
```

### 10.2 设施候选查询

**输入：**

```json
{
  "municipalityId": "string",
  "latitude": 35.0,
  "longitude": 139.0,
  "facilityTypes": ["string"],
  "accessibilityNeeds": []
}
```

**输出：**

```json
{
  "dataStatus": "confirmed | not_realtime | unknown | unavailable",
  "source": {
    "name": "string",
    "url": "string",
    "updatedAt": "ISO-8601"
  },
  "facilities": []
}
```

### 10.3 规则计算

**输入：**

```json
{
  "mode": "disaster",
  "directDangerCleared": true,
  "environment": "indoor | outdoor | transit",
  "answers": ["yes | no | uncertain"],
  "needsHelp": false,
  "locationStatus": "available | manual | unavailable"
}
```

**输出：**

```json
{
  "ruleVersion": "string",
  "userState": "safe | uncertain | danger | need_help",
  "cardId": "string",
  "nextActions": ["string"],
  "sourceIds": ["string"]
}
```

规则接口不得调用生成式AI决定`userState`或`cardId`。

## 11. P0验收标准

比赛版本只有同时满足以下条件才视为P0完成：

1. 手机浏览器可打开PWA，无需注册；
2. 中文、英文、日语可推荐并手动切换；
3. 灾害模式主流程可从入口走到沟通卡；
4. 用户仍处于直接危险时不会进入复杂问答；
5. 三个风险问题均支持“是/否/不确定”；
6. 相同输入稳定得到相同状态和行动卡；
7. 至少一项开放数据实际改变设施候选结果；
8. 设施候选显示来源、更新时间和实时状态限制；
9. 定位失败时可手动选择行政区域并继续；
10. AI接口失败时核心规则仍可运行；
11. 网络异常时不出现空白页或误导性结果；
12. 页面提供多语言全屏沟通卡；
13. 不保存用户位置历史；
14. 主Demo在两分钟内完成；
15. 主Demo连续演示三次成功；
16. PPT、讲稿、页面和规则版本表述一致。
